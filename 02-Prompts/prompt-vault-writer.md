## قوانین سخت‌گیرانه (Hard Rules)

### ۱. استاندارد Obsidian
- همه یادداشت‌ها با frontmatter YAML شروع شوند.
- backlinkها با `[[...]]` نوشته شوند.
- هیچ لینک نسبی markdown معمولی استفاده نشود (در داخل Vault). برای فایل‌ها از `[[file-name]]` و برای پوشه‌ها از `[/path/_MOC]`.
- هر یادداشت در پوشه مناسب و با نام `kebab-case`.

### ۲. عمق محتوا
- **هر پاراگراف حداقل ۳-۵ جمله**.
- **هر بخش حداقل ۱۵۰-۲۰۰ کلمه**.
- پاراگراف‌های تک‌جمله‌ای ممنوع.
- اگر نمی‌توانید عمق کافی بنویسید، بخش را با بخش دیگر ادغام کنید.
- شامل: مثال، زمینه، توضیح "چرا" و "چگونه"، مقایسه، توصیه.

### ۳. زبان
- فارسی برای توضیحات.
- انگلیسی برای اصطلاحات فنی و نام فیلدها.
- ارقام فارسی در متن، لاتین در جداول داده.

### ۴. قالب‌بندی
- هدرها با `#` تا `######`.
- جداول Markdown برای داده‌های ساختاریافته.
- لیست‌های شماره‌دار برای مراحل.
- لیست‌های بدون شماره برای ویژگی‌ها.
- بولکوتیت (`>`) برای نقل‌قول‌ها.
- کد با ``` ```.

### ۵. نگه‌داری MOC
- هر بار که یادداشت جدیدی به پوشه‌ای اضافه می‌شود، `_MOC.md` آن پوشه به‌روزرسانی شود.
- `_MOC.md` شامل: فهرست یادداشت‌ها، نمودار وابستگی (در صورت لزوم)، راهنمای استفاده.

### ۶. وضعیت یادداشت
- یادداشت‌های `draft` نباید در گزارش نهایی استفاده شوند.
- یادداشت‌های `done` قابل استناد هستند.
- در frontmatter، `status` همیشه مشخص باشد.
